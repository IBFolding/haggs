# Hosted output recovery — local candidate, activation blocked

`HAGGS_HOSTED_OUTPUT_RECOVERY=1` opts Comfy Cloud media jobs into an owner-scoped server journal. It is absent/off by default. This is source implementation with local fixtures, not a live privacy/recovery certification. No production migration or credential configuration was performed.

Before provider dispatch, the server writes a random intent ID bound to the authenticated Haggs owner, selected output node, own/platform credential scope and an HMAC credential fingerprint. Clients cannot directly write the table. RPC writes require both the owner's JWT and the existing server-only webhook secret. The key itself and signed provider URLs are never journaled or returned. The accepted provider job ID is persisted before polling; completed file identity is persisted before downloading. A lost acceptance response remains a dispatching/manual-review record and must never authorize blind resubmission.

Completed bytes use one deterministic private pathname per journal ID. Before the write, an atomic owner-bound SQL claim records byte count, SHA-256 and quota reservation. Writes never overwrite. A lost write response leaves `saving`; recovery verifies the existing private object's exact bytes/hash before quota settlement and journal completion. An absent/mismatched uncertain object cannot trigger another upload. The quota finalizer is guarded against releasing a claimed uncertain hold, under the same owner advisory lock. User-requested deletion cancels the matching record; a separate explicit reconciliation checks absence for a previously confirmed saved copy before freeing stale accounting. In-flight saving claims cannot be dismissed that way.

The Gallery account-output panel lists only the requesting owner's journal and uses the server-selected matching key for that record. It never lists all jobs from a shared platform key. It can reconcile existing verified outputs while writes are paused, but cannot create a new private object until writes resume. Saved outputs are added to Gallery once per journal marker. Existing account Files deletion and quotas remain in use. Authorization is checked again on each API call and SQL operation; stale account-switch responses do not update the active UI.

If the provider original is unavailable and no durable private copy was verified, the UI says that metadata cannot recover deleted bytes. It never submits a new generation. A verified private copy can still be recovered when the provider original is gone. Provider status/credential failures do not imply that a new job should be submitted. Credential/HMAC-secret rotation can invalidate pending bindings and requires an approved migration/reconciliation plan; never silently rebind records to another account.

It passed real SQL owner isolation, forbidden client writes, bad-secret rejection, concurrent owner claim, simultaneous cleanup protection, idempotent settlement and deletion accounting. Reapplying against a changed quota function is rejected before schema mutation.
- The first local cluster start was blocked by sandbox shared-memory restrictions; the explicitly approved local-only retry passed. This is unrelated to the denied Supabase test-project Terminal operation, which was never retried or accessed through another path.

Private provider references now become authenticated bytes before provider upload; no app URL/session is forwarded to the provider.
