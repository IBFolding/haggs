# Managed Comfy API adapter: handoff

`src/providers/comfy-managed.ts` is a v2 transport prototype. It has no submission route or settings UI, and **all managed uploads and job submissions are blocked**. This is intentional: a provider-enforced per-job cost limit, billing reservation and reconciliation have not been integrated. A quoted price or a client-side timer is not a spending cap. Do not enable managed runs until those controls are designed and verified.

`GET /api/managed/jobs/[submission]` is a preliminary authenticated status/recovery surface. It is off unless `HAGGS_MANAGED_RECOVERY_ENABLED=1` and trusted server-only deployment configuration exists; it checks the account and exact deployment before looking up a journaled job, returns no provider or signed URLs, and does not submit or save outputs. The migration and route have not been tested against hosted Supabase or a real deployment. Keep it disabled until billing, durable output and recovery are verified.

The prototype validates the deployment origin and same-origin job links; follows only explicitly allowlisted HTTPS signed-output hosts without forwarding the API key; limits output bytes; submits with a unique idempotency key and never retries uncertain submissions. It accepts a loopback v2 proxy only for explicit non-production testing. A local CPU test uploaded two sample videos and audio, submitted HaggsWorldOrchestra through the official `comfy-api-proxy`, polled it and persisted a three-second H.264/AAC MP4. This does not verify managed execution or model inference.

`managed-job-journal.ts` and the new migration provide a server-written, owner-readable job journal. An atomic insert records dispatch intent before submission. Duplicate submissions do not reach the provider; uncertain outcomes remain pending and can be located through the provider's metadata-filtered job list. Ownership, invalid provider URLs, no-result and ambiguous matches fail closed. Local PostgreSQL tests exercised the SQL functions, duplicate prevention, secret check and owner isolation. The migration has NOT been applied to the live database. The journal is not wired into an app route; end-to-end operation through Supabase/PostgREST is unverified. A caller must authenticate the user, use server-controlled configuration and use `submitJournaled`/`recoverJournaled` before enabling a route.

Before integrating with Haggs workflow screens:

1. Provision a compatible Comfy API Build containing the exact verified node pack, compatible ComfyUI and dependencies, and any licensed models. The account, GPU, region, availability, worker and storage rates, spending policy and access scope need explicit review. Keep the platform API key server-side.
2. Implement a server-enforced budget and concurrency reservation covering startup, execution, idle tail, storage and partner-node charges; establish a conservative maximum or keep the run disabled. A zero minimum worker count limits idle compute but does not eliminate storage cost. Do not conflate an estimate or cancellation timer with a provider hard cap.
3. Review the migration and deploy it only as part of an authorized production release. Wire verified per-user authentication and the journal to submission, status and recovery routes. Test the actual Supabase/PostgREST path, storage reservations, reconciliation, concurrent requests, and failure scenarios. Comfy Cloud does not support metadata job listing; this recovery path is for a managed deployment.
4. Configure a narrowly scoped signed-output host allowlist from trusted server configuration. Confirm the real provider redirect host, file size and MIME checks, expired URL behavior, output storage and recovery on a real deployment. Never accept the allowlist from a user request.
5. Integrate explicit destination selection, catalog/build compatibility, auth, accurate charges and user-visible status in the existing UI. The legacy local `/object_info` transport and Cloud v1 route are not interchangeable with the managed v2 endpoint. Test cross-user isolation, duplicate clicks, failures and billing paths.
6. Run a low-cost, explicitly bounded end-to-end test after infrastructure and budget are approved. Preserve the live Grey Room, landing page, Neon Courier and provider connections.

Comfy publishes GPU pricing from $1.75/hour for RTX PRO 6000 MIG (48 GB), billed per second, and network storage at $0.20/GB/month; current account availability and rates must be confirmed at deployment time. Workers bill for startup and a short idle tail, and storage can continue while a deployment is paused. See https://www.comfy.org/pricing and https://docs.comfy.org/development/serverless/overview. API contract: https://docs.comfy.org/api-reference/v2/overview.
