# Managed Comfy API adapter: handoff

`src/providers/comfy-managed.ts` is a v2 transport prototype. It has no app route or settings UI, and **all managed uploads and job submissions are blocked**. This is intentional: no provider-enforced per-job hard cost limit, durable account reservation, concurrency control, and recovery process have been integrated. A quoted price or a client-side timer is not a spending cap. Do not enable the managed branch until these are designed and verified.

The adapter validates the deployment origin and prevents credentials being sent to external job/output URLs; submits with a unique idempotency key; never automatically retries an uncertain submission; polls the returned job URL; and returns a completed job ID if output storage fails. It accepts a local loopback v2 proxy only when `localTest` is explicit. A real local CPU test uploaded two sample videos and audio, submitted HaggsWorldOrchestra via the official `comfy-api-proxy`, polled it and persisted a three-second H.264/AAC MP4. This does not verify a managed deployment, production access, LTX/H3 model inference, or provider charges.

Before integrating with Haggs workflow screens:

1. Provision a compatible Comfy API Build containing the exact verified node pack, compatible ComfyUI and dependencies, and any licensed models. The account, GPU, region, availability, exact worker and storage rates, spend policy and access scope need explicit review. Never put a shared platform API key in the browser.
2. Implement a server-enforced budget and concurrency reservation that covers startup, execution, idle tail, storage and partner-node charges; establish a conservative maximum or keep the run disabled. A minimum worker count of zero limits idle compute but does not eliminate storage cost. Do not conflate an estimate or cancellation timer with a hard provider cap.
3. Persist submission IDs and provider job IDs before submission/recovery, with an authenticated per-user owner check. Resolve uncertain submissions via provider job listing and metadata; never repeat a job just because a request times out. Audit provider retention and reconcile billing before release.
4. Implement and test v2 assets and outputs on a real deployment. The prototype rejects redirects; managed asset content may redirect to a short-lived signed storage URL. Add a carefully validated redirect flow that **never forwards the bearer token** and persists the output. Handle file size limits, MIME verification, expired URLs and recovery.
5. Integrate explicit destination selection, catalog/build compatibility, auth, storage preflight, accurate charges and user-visible status in the existing UI. The legacy local `/object_info` transport and Cloud v1 route are not interchangeable with the managed v2 endpoint. Test cross-user isolation, authorization, duplicate clicks, failure and billing paths.
6. Run a low-cost, explicitly bounded end-to-end test after the infrastructure and budget are approved. Do not alter the existing live Grey Room, landing page, Neon Courier, or provider connections.

Comfy publishes GPU pricing from $1.75/hour for RTX PRO 6000 MIG (48 GB), billed per second, and network storage at $0.20/GB/month; current account availability and rates must be confirmed at deployment time. Workers bill for startup and a short idle tail, and storage can continue while a deployment is paused. See https://www.comfy.org/pricing and https://docs.comfy.org/development/serverless/overview. API contract: https://docs.comfy.org/api-reference/v2/overview.
