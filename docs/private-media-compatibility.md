## Reversible rollout

1. **Inventory, no mutation.** Record the exact trusted public-store origin, owner-scoped object metadata, byte counts and independently streamed SHA-256; export account projects, Explore posts and storage accounting. Include browser-only project exports. Record version/hash of every source document. Inventory manifests contain private URLs and must stay in approved private operator storage, never PRs or public logs.
2. **Test environment only.** Keep the workflow task's `haggs-safety-test` (`bhscymqhodllcmreblgx`) bucket/schema experiments coordinated. Its `haggs-synthetic-private` bucket is Supabase, not the proposed Vercel backend. Use two real synthetic auth sessions, an anonymous client and an approved private Blob test store. Never copy production credentials or customer objects into this test.
3. **Reader-first deployment.** Review/deploy private read routes and mixed-store accounting with `HAGGS_PRIVATE_MEDIA_WRITES` unset. Configure the separately approved private-store read/write credential while new writes remain legacy. Verify direct anonymous private-store denial, owner success, wrong-owner denial and no URL/token leakage. Existing legacy paths continue serving.
4. **Sharing schema.** Back up the actual post constraints and rows. Validate/apply the additive owner-bound URL constraint in the test project first. Production application requires the normal approval and verified schema history. Keep the expanded constraint on rollback while private posts exist; restoring a public-only constraint would invalidate them.
5. **Activate new private writes.** Only after all acceptance gates pass, set `HAGGS_PRIVATE_MEDIA_WRITES=1`. The credential alone does not activate writes. Missing private credential fails before upload/generation. Both upload endpoints remain mounted: their fixed store credentials validate in-flight completion callbacks; an endpoint for the inactive write mode refuses new upload tokens. Allow at least the existing 15-minute upload-token window, plus observed upload duration, before assuming old public uploads are drained.
6. **Copy legacy objects.** `planLegacyCopies` creates deterministic private destinations from an exact trusted-origin, owner-bound inventory. Copy without overwrite or deletion, then independently verify bytes/hash and private raw-storage denial. Failed/uncertain copies are investigated; no blind duplicate copy. Budget temporary duplicate storage explicitly. Do not charge a customer's quota twice: real ledger reconciliation must be designed/tested atomically before production copies are included in the normal mixed-store listing.
7. **Repoint snapshots, preserve sharing intent.** Only `verifiedReferenceMap` output may rewrite exported JSON. Keep original and rewritten versions. Apply by per-document compare-and-swap version/hash; concurrent edits stop the batch for reconciliation. Preserve existing explicit public posts by changing each post URL to its verified private reference in an owner-checked transaction. Never infer consent to publish an unshared object. Projects with missing browser-only references remain blocked from retirement.
8. **Observe, then separate retirement approval.** Verify every known reference, shared embed, owner workflow and rollback snapshot. The planner exposes no deletion/revocation operation. Existing public URLs stay accessible until an approved retirement operation removes/restricts their original objects and any relevant CDN behavior is checked. Copies and reference updates alone do not revoke public URLs.

## Rollback

Pause **new writes** by clearing `HAGGS_PRIVATE_MEDIA_WRITES`; retain the private credential, reader routes, sharing constraint and both upload callback endpoints so existing private media and in-flight uploads continue working. Do not roll the application back to a revision that cannot read private references. Revert a migrated JSON snapshot using its saved original only if its current version/hash still matches the migration's output; otherwise reconcile the user's newer edits. Repoint explicitly shared posts to original URLs only if those originals remain available and doing so preserves the owner's current sharing choice. Leave verified private copies intact until an approved retention decision. No automatic link retirement is reversible after third parties have downloaded content.

## Required acceptance before production activation

Real synthetic upload of image/audio/video; no-auth/wrong-owner raw and app reads; owner playback and range seeking; explicit share, reload and unshare; both API-cookie and API-bearer renders; save/reopen on another session; quota failure before provider work; completed upload callback after write-mode rollback; account deletion/ledger reconciliation; Playable atlas, standalone exports, profile avatar, provider-save recovery and browser-only legacy references. Pending keys or permissions are prerequisites, not permission inferred from elapsed time.

## Compatibility follow-up (local candidate)

- **Playable atlas:** private atlas bytes are now read by the authenticated parent and embedded unchanged as a raster data URL. Full atlas dimensions/transparency are preserved because the bytes are not decoded/resized. Regular private art also resolves in the parent before entering the opaque sandbox. Failure reports a private-image error instead of passing an unreadable URL into the game. No sandbox permission was expanded. Collision file for Playable coordination: `src/app/playable/code-frame.tsx`; the implementation is isolated in this worktree, not applied to the Playable task's branch.
- **Raster export packaging:** `packagePrivatePictures` packages private raster references on explicit invocation, with bounded streaming, exact-byte preservation, same-origin credentials and no redirects. Public references are left unchanged. It aborts on unauthorized/active-content media. The current source has no complete standalone game export front door to wire this into; general project/Blender/audio/video bundle export remains pending. Do not call standalone export complete from the helper tests.
- **Avatar:** the private reader now permits the exact current public profile picture owned by the same account, in addition to exact public media posts. Changing a private picture on an already-public profile requests explicit publication confirmation; first Explore publication names the profile picture in consent. Remove picture is available and saving removes its profile reference. The draft schema includes an owner-bound private raster constraint for profiles. No live schema was changed. Real DB/policy/session verification remains required. An avatar used in a post remains public until both references are removed; unshare copy explains this.
- **Failed durable saving:** temporary provider outputs are preserved with a warning that the URL is not private storage and may expire. Studio/Gallery recording retains the warning across JSON reload; Gallery displays it. Saving attempts do not resubmit generation. This provides honest recovery status, not durable server-side recovery after the provider link expires. An owner-bound durable provider-job journal, real retry-save action and hosted acceptance are still needed; no blind paid retry or output discard was added.

Synthetic focused tests verify exact atlas/export bytes and URL stripping, unauthorized/active-content failure, output preservation on save failure, warning persistence, and clearing a warning after successful storage. These do not certify browser rendering, actual profile SQL, real provider recovery or the live storage backend.

## Export and recovery follow-up

Project Library Export now embeds supported app-media references in the existing readable `.haggs.json` envelope. Supported sources are authenticated private app URLs, local media URLs, existing public Blob objects and already embedded data. Supported bytes are PNG/JPEG/WebP, MP4/WebM/QuickTime, MP3/M4A/AAC/FLAC/WAV. Reads are deduplicated and bounded to 64 MB per file / 128 MB total; source projects remain unchanged. External provider URLs and arbitrary web URLs are not fetched/credentialed and remain dependencies. Unsupported model/other files cause an explicit error. A full project with external dependencies must not be described as offline-complete.

Library Import detects embedded media, asks to import it into the user's storage, then restores files through the normal upload function and quotas before saving/replacing the project. Deduplication preserves shared references, including JSON-encoded sheets. A failure aborts project replacement and reports that already uploaded files may exist; it never automatically deletes those files or silently retries. The original project snapshot is preserved. Imports over 180 MB are refused before parsing.

Playable's code-game studio now offers **Download standalone HTML**. Supported 2D code games package all Haggs pictures and render inside an `allow-scripts` iframe with no same-origin permission; the existing game's CSP remains inside it. Export refuses unresolved external asset dependencies and 3D runtime dependencies. Template-game export, 3D-runtime bundling, arbitrary models, Blender packages, large-film archives and external-provider dependencies remain outside this implemented path. The collision file `src/app/playable/[id]/studio.tsx` must also be reconciled with the Playable task at integration; its separate checkout is untouched.

`output-recovery.ts` implements a stable owner/job/filename/subfolder record and recovery state machine. It persists provider file identity, never a key or expiring signed preview URL. Recovery requires a store's atomic owner-bound pending→saving claim. Saved results are idempotently returned. A lost save response remains uncertain until `findSaved` reconciles the deterministic storage reference; it is never blindly uploaded/generated again. A local filesystem-backed fixture closes/reopens the journal, denies the wrong owner, recovers independently of a preview URL, simulates lost response and reconciles one saved result. This fixture is not a production database adapter or distributed-claim certification.

Comfy Cloud's runner now exposes `onOutputReady`, invoked before output download and carrying stable file identity. It can be supplied by an approved authenticated journal adapter; no default production adapter/flag is activated here. Hosted implementation still needs server-written owner/credential-scope binding (clients must not forge shared-platform-key job identities), RLS, durable atomic claims, completion reconciliation, provider-retention handling, authenticated list/recover UI and isolated real-session tests. If the provider deletes its original file, the journal alone cannot recover its bytes; independent durable output storage is necessary before that deletion.

The separate test project's Terminal access was denied by computer-use safety restrictions. This task did not retry that action through shell, API credentials or another path. Tests here use disposable local files, synthetic metadata and injected fetch/storage adapters only.

Owner-signed-in Gallery recovery now persists up to 500 sanitized references in the browser's existing durable KV, scoped by Haggs user ID. Signed previews and keys are discarded before persistence. Reloading restores those references even if they are no longer among the provider's 40 recent outputs. Account switches cancel stale UI commits. Add verifies job/file membership through the authenticated job endpoint before reading the original, then uses normal private saving/quotas. Anonymous/local-only sessions do not get this account-scoped persistence, and shared platform-credit jobs are deliberately not listed using the platform key. Provider-deleted originals cannot be restored from reference metadata alone. Clearing browser data also removes this local journal; hosted server durability remains pending.

Media envelopes use `haggs.media/1` attachments outside the existing project/sheet data so large media does not bypass or overflow sheet text validation. The project is prevalidated with short attachment references, media restored via uploads, then validated again with normal media URLs. Standalone ordinary sprites use the same browser transparency preparation as the preview; atlases remain unmodified.
